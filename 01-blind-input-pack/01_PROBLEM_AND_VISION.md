# 01. 项目背景、痛点洞察与产品愿景（盲审纯输入包）

> **致独立评估者**：本文档仅陈述发起人的原始问题洞察、功能构想、约束边界与目标场景，**不含**最终方案结论或任何审稿意见。请先结合 `02_EXISTING_EMPIRICAL_EVIDENCE.md` 与 `03_EVALUATION_WORKFLOW_SOP.md` 独立完成资料查证与可行性评估。

---

## 1. 发起人核心痛点洞察（Why Now）

当前 AI 学习工具呈现明显的两极割裂：
1. **大模型聊天框 / 一键总结类工具（高流畅、高幻觉、零复利）**：
   - 满屏流畅总结制造“看懂了”的**掌握幻觉（Illusion of Mastery）**；
   - 把“主动提问”的输入成本全部甩给学生（打字提问摩擦高，真正卡壳时往往连“该问什么”都说不清）；
   - 聊完即散，跨课程、跨章节、跨周的学习证据无法沉淀为长期复利。
2. **传统笔记软件 / 卡片复习软件 / 重型知识库（高门槛、高折损）**：
   - 需要大量手工建卡、整理目录和手动复习排期，多数大学生在第 7 天前放弃维护；
   - 笔记、题库、错题本、原始课件、AI 问答彼此割裂，阅读、做题和复习各自为政，缺乏统一的状态追踪。

**核心假设**：大模型已经具备很强的“大脑”，但当前缺少一套**低摩擦交互入口 + 可核查证据引擎 + 个人长期复利闭环**的集成学习平台，让 AI 从“一次性答题聊天框”进化为“**作为个人复利的集成式 AI 助教**”。

## 2. 发起人的完整构想（集成平台，不局限于问答）

平台定位为一个**集成学习工作台**（涵盖多源资料摄入、知识库/笔记、题库/做题、错题与复习调度、微打卡与按需问答），核心由以下能力支柱组成：

### 支柱 A：低摩擦“变密度交互”学习流（解决“不想开始”与“以为自己会了”）
1. **低密度破冰大纲（快速进入）**：摄入资料后，先输出大白话、低密度结构地图，帮助快速建立全局心智模型，并支持学生一键跳过已知板块。
2. **零打字微诊断（主动暴露盲点）**：逐块抛出极轻量的交互微诊断（辨误、补关键步、二选一等 + 一键“我卡住了”），不靠自由打字提问，直接暴露真懂 vs 伪懂。
3. **回归原材料的精准溯源 + 按需局部 AI 问答**：
   - 答对快速过关；
   - 答错或卡壳时，**原地回指原始材料精确位置**（如 PPT 原页图、PDF 页码、文档段落/行号），并**只在此时按需唤起锚定当前原页/当前考点的局部 AI 追问**（先给快捷追问胶囊，不够再自由追问），避免一上来满屏聊天框，同时解决静态拆解讲不透的问题。
4. **高密度个性化复习总纲（精准复盘）**：收尾时输出高密度、专业术语完整、可导出的复习总纲，并按本轮真实作答证据自动分层（卡壳/错题块标红置顶展开，已过块标绿折叠）。

### 支柱 B：同一 `concept_id` 的双层知识索引与个人复利底座
1. **双层知识索引（人读视图 ↔ AI 视图）**：
   - 共用同一知识点编号、来源映射与版本，避免双库割裂。
   - **人读视图**：清晰的定义、推导步骤、类比、易错点、原文定位、错题解析、笔记与复习任务。
   - **AI 视图**：紧凑结构化的机器上下文（适用边界、先修关系、来源片段 ID、历史作答与提示曝光证据、未解决错题、下一步教学动作），供教学决策与精准检索直接调用。
2. **多源学习资料接入（规划层面）**：
   - 首期优先吃透常见课程资料（PPT / PDF / Word / Markdown 笔记 / 课堂转写文本），中长期扩展至学术论文、网课视频/字幕、考研或考试真题集等多源形态。
3. **四类数据严格隔离（防知识污染）**：
   - 原始资料位置（`SourceMap`）、派生知识点/笔记（`LessonModel`）、学生行为与作答证据（`LearnerEvidence`）、系统暂定推断（`Inference`）严格分存。
   - AI 生成的新笔记/归纳以候选变更（`ChangePlan`）沉淀，不污染原始资料；学生错题记录为学习证据，不污染学科事实。

### 支柱 C：反“伪掌握”的证据驱动闭环（笔记 + 题库 + 错题 + 复习 + 微打卡）
1. **严格区分“行为”与“掌握”**：
   - 看过笔记 ≠ 掌握；看提示/看答案后改对 ≠ 独立掌握；同题反复刷 ≠ 掌握；
   - 需在**不同题族（换表征或推理结构，而非仅换数字）且无提示、未看答案**的条件下独立答对多次，才进入初步掌握，并衔接间隔重复复习（如 FSRS 思路）。
2. **隐含且可解释的动态用户画像**：
   - 结合显式偏好（目标、可用时间、讲解风格）+ 真实作答/提示/停留证据 + 可查看且可推翻的系统诊断依据，驱动个性化题库推荐、错题回炉、增量笔记更新与复习排程。
3. **低负担微打卡与正向反馈**：
   - 行动打卡与知识掌握状态严格分开计算；支持缩小/暂缓/重启，核心定位为“降低学习启动难度、维持持续复利”，而非惩罚性监控。
4. **系统可靠性与低延迟底线**：
   - **不知道就拒答**：资料未覆盖的问题明确告知证据不足，严禁凭通用知识冒充材料原文胡编；
   - **快慢路径分离**：阅读记录、判分、状态机更新、题库分支与打卡全走本地确定性逻辑（0 模型延迟）；日常解释与原页局部问答走有界检索 + 单次快模型；资料解析、知识图谱/双层索引构建与候选出题走后台慢路径。

## 3. 团队约束与目标场景（1B 绑定竞赛 + 真实长期可用）

- **目标用户**：首要切口为**大学生专业课/竞赛/自学群体**（理工、CS、经管金融等高概念密度课程），中长期覆盖考研、论文精读与跨学科个人终身知识复利。
- **团队资源画像**：高校在读学生自建小团队（核心开发 1–3 人，兼具计算机/AI 工程与经管/产品背景），预算有限（需控制 LLM API 单位成本，优先使用正规官方 OpenAI 兼容 API 或低成本/免费额度，严禁违规反代第三方客户端额度）。
- **目标定位（双轨验证）**：
  1. **真实产品可用性**：先确保个人及同学在真实课程学习中愿意持续使用并产生复利，而非一次性炫技 Demo；
  2. **竞赛复用路径**：规划需同时评估对高校竞赛的适配性与竞争力，包括：
     - **近期/中期**：挑战杯（需评估更适合“大挑”科技发明/学术作品还是“小挑”创业计划）、官方高校 AI 应用赛事（如教育赛道应用赛）；
     - **中长期延续**：大学生创新创业训练计划（大创）等半年至一年期项目。
- **当前阶段诉求**：**先不进入详细 UI 稿或具体代码/数据库设计**，优先完成客观可行性调研并把**完整的功能蓝图、边界划分、分期节奏与风险权衡**讲清楚。
