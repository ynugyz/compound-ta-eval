- **实验材料**：一份 27 页真实技术课件 PDF（含架构图与数学公式），切分为 8 个核心知识块（覆盖全章 P.05–P.25），配套 27 张原页高清渲染图与逐字核验的 `evidence_span`（100% 文本精确匹配）。
- **交互闭环**：手机端真实体验 B 组三段式流程（低密度大白话地图 + 可勾选跳过已知块 → 零打字 3 选 1 / 辨误 / 补步微诊断 + “我卡住了” → 答错/卡壳原地展开原页图与原文证据 → 高密度红绿折叠复习总纲）。
- **实测埋点事实（N=1，发起人手机端首轮完整通关）**：
  - 首次交互时间：`13.7 秒`（主动勾掉已掌握的前 2 个基础块 `b1/b2`）；
  - 全章完成总时长：`146.4 秒`（2 分 26 秒），完成率 `100%`，自由打字输入 `0 次`；
  - 6 个作答块中 5 题一次答对（单题停留 `7.2–20.0 秒`），第 7 块（`b7`，对应 P.19）选错（停留 `21.6 秒`，全章最长），且在选错 `10 秒` 后**主动点开放大原页图 P.19**。
- **一手定性反馈与暴露出的新需求**：
  - 整体节奏“确实舒服、总体效果很好”，跳已知块 + 零打字微诊断显著降低了阅读启动摩擦；
  - 暴露出两个高优先级迭代点：① **微诊断问题设计质量**（需避免变成低价值记忆题，需提升概念区分度与反直觉陷阱质量）；② **回归原页材料时按需跳出局部 AI 问答**（在 `b7` 选错并放大原页的瞬间，静态解析不足以彻底解惑，需要原地唤起锚定当前页的局部追问）。

## 2. 前期后端引擎与证据可靠性工程实验数据

在另一条独立的单章后端引擎实验中（聚焦大学《概率论》条件概率/全概率/贝叶斯单章，16 份真实课堂转写 + 结构化笔记 + AI 摘要卡固定快照，SQLite + FTS5）：

- **双层索引与契约隔离可行性**：
  - 实现了只读课程库（`mode=ro`）与可写学习证据库分离、SHA-256 快照校验、14 条跨层引用边 100% 命中锚点、6 档状态机（`UNKNOWN / NOT_YET / DEVELOPING / PROVISIONAL / REVIEW_DUE / NEEDS_REVIEW`）与异题族（`item_family_id`）晋级规则，单机自动化回归 `308/308` 全绿。
- **暴露出的真实工程天花板（重要风险事实！）**：
  1. **纯 0 模型词法/规则检索有明显天花板**：在已知测试集 `final-30` 上可做到 Top-5 召回 `24/24`、包外拒答 `6/6`、过拒 `0/18`；但在全新零术语重叠场景的盲测 `holdout-10` 上，虽然守住了安全底线（包外拒答 `2/2`、零编造、30 对实答引文 `100% supported`），召回跌至 `5/8`、过拒 `2/6`、澄清 `0/2`。说明**仅靠 BM25/规则无法泛化到复杂自然语言新提问，必须结合有界快模型或真实语义检索**。
  2. **扫描版 PDF / 数学公式提取仍是硬骨头**：真实大学教材 PDF 常无文本层（纯扫描件）或含复杂公式排版，自动解析失真会直接破坏下游题库与证据溯源的可信度。
  3. **题库生产成本极高**：上述单章 24 题（6 能力目标 × 4 题）依赖大量人工审核与精度校验（曾揪出计算小数精度误差与课堂转写噪声），若扩展到“用户任意上传多学科资料自动出高区分度好题”，**自动出题质量与防幻觉验题**将成为决定平台成败的核心瓶颈。
  4. **延迟来源诊断**：实测全本地读取数百篇 Markdown 笔记仅需 `< 0.1s`；现有重型开源 AI 助教之所以响应慢，主要源于默认开启高思考强度 + 全局工具多轮往返 + 网络重试。快慢路径分离在工程上已被证实是刚需。
